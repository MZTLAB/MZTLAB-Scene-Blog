# MZTLAB · Scene SSG 迁移可行性

> 适用版本：3.0.0-beta2
>
> 本文是重构方案附录 B 的长期版本：记录“公共页从 SSR 迁移到 SSG（构建期预渲染）”的可行性、阻塞项、3.0.0 已完成的预留，以及未来迁移的检查清单与工作量。
> 3.0.0 **不实现 SSG**；本版只确保迁移时不需要重写页面模板与数据访问层。

---

## 1. 结论

- **方向可行，但不属于 3.0.0 范围**。SSG 的核心收益（运行期零渲染、TTFB 更低、抗流量抖动）成立；主要成本不在“预渲染”本身，而在四件基础设施：构建/发布管道、静态资产托管切换、数据就绪（派生图必须构建前 ready）、以及重建触发延迟。
- 3.0.0 的推进顺序是：先完成 R1–R7 预留，使“页面数据 = 单一聚合接口 + 纯函数渲染 + 已物化的媒体元数据”。**R1–R7 已全部闭环**；未来迁移只需新增构建器与发布流程，不需要重写页面模板与数据访问层。
- 互动功能（站内评论）在 3.0.0 已移除，公共页不再有随请求变化的读数据，这是本版对 SSG 最重要的一项使能。

---

## 2. 3.0.0 现状与 SSG 目标

| 维度 | 3.0.0（本版） | SSG 目标 |
| --- | --- | --- |
| 公共页渲染 | Astro SSR，每次请求组装 | `astro build` 预渲染为 HTML 文件 |
| 数据来源 | 每个公共页恰好调用一次 `getBootstrap()` → `GET /api/bootstrap`（`page_data()`） | 构建期调用同一函数/接口取数 |
| 托管 | Astro 进程（含 `/_astro` 资产） | 接入层 nginx 静态托管（`/_astro` 可长期缓存） |
| 发布延迟 | 即时 | 重建完成（目标 ≤ 2 分钟） |
| `/admin` | Astro SSR | 保持 SSR（唯一需要 Node 运行时的路径） |
| 搜索 | SSR 页面 | 静态空壳 + 客户端 `fetch('/api/search')` |
| 动态数据 | 无站内评论、无浏览量 | 无（本版已具备） |

## 3. 3.0.0 预留闭环状态（R1–R7）

| 预留 | 设计要求 | 3.0.0 状态 | 说明 |
| --- | --- | --- | --- |
| **R1** 聚合读接口 | 每页只需 1 个数据请求，且可在构建期无请求上下文调用 | **已实现** | `app/services/page_data.py` 的 `page_data()` + `GET /api/bootstrap`（`route`/`slug`/`page` 等参数）；前端所有公共页恰好调用一次 `getBootstrap()`（无逐接口取数），不读 cookie/会话/UA。 |
| **R2** 路径式分页 | 分页进路径，旧 `?page=` URL 301 到新路径 | **已实现** | `/tags/{tag}/page/{n}` 与 `/categories/{category}/page/{n}` 路由；旧 `?page=N` 由 `frontend/src/middleware.ts` 301 到路径；`Pagination.astro` 输出路径 URL。按计划范围，`/photos` 与 `/projects` 保持第 1 页。 |
| **R3** 渲染上下文审计 | 公共页不得读 cookie/session/UA/请求头，不得用 `?page=` 分页 | **已实现** | `python -m app.scripts.check_public_render` 已接入 CI，当前扫描 32 个文件、0 处请求上下文读取（硬门禁）。 |
| **R4** 派生图就绪 | 媒体元数据已物化，构建期不改写 HTML、不触发编码 | **已实现** | `media.derivative_set` 物化 ready 产物；`images.image_payload()` 只读、未就绪回退原图；`/media/_v/...` 只服务已存在的派生行。 |
| **R5** 重建任务形状 | 定义 `jobs.kind='rebuild_site'`，但本版不实现执行器 | **已实现（形状）** | `jobs` 表接受该 kind，API 可创建/查询；worker 永不 claim，行保持 `queued`，未来只需插入执行器。 |
| **R6** 资产路径规则 | 页面不引用运行期临时路径；资产 URL 可长期缓存 | **已实现** | `/_astro/*` 由构建产物决定；派生图 URL 由 token 决定；无“本次请求生成”的路径。 |
| **R7** 5xx 语义 | 页面与 API 的错误响应形状稳定 | **已实现** | 页面有 `/404`、`/500`；API 统一 `{"error": {...}}` 错误体；未处理异常不泄露堆栈。 |

> 结论：R1–R7 已全部闭环。迁移前剩下的都是基础设施工作：构建/发布管道、静态资产托管切换、重建触发与失败回退，以及按本文检查清单做一次演练。

## 5. 备选方案

| 方案 | 收益 | 成本/风险 | 结论 |
| --- | --- | --- | --- |
| A. Astro 预渲染（SSG）+ 静态托管 | 运行期零渲染、TTFB 最优 | 构建/发布管道 + 资产托管切换 + 重建延迟 | **未来目标**；3.0.0 只做预留 |
| B. 保留 SSR + 接入层短 TTL `proxy_cache` | 不改渲染模型，TTFB 改善明显 | 缓存失效与 Cookie/`Set-Cookie` 排除必须正确；延迟以 TTL 计 | **可选过渡**，配置要求见 [`EDGE.md`](EDGE.md) 的缓存章节 |
| C. 保持 SSR + 应用侧 ETag/短缓存（本版默认） | 零新增基础设施，改动最小 | 每次请求仍有组装成本 | **3.0.0 采用** |

## 6. 未来工作量

不含 3.0.0 已投入的预留成本，预估 **5~8 人日**：

- 构建器与发布管道（B5）：2~3 人日。
- 资产托管切换与 `/admin` 协调（B6）：0.5~1 人日。
- 重建触发、合并、失败保留与告警（B7）+ sitemap/RSS（B9）：1~2 人日。
- 规模压测与增量/分区（B12）：1~2 人日。
- 另需一次 staging→生产演练；若 B6 选择“继续由 Astro 提供资产”，可减约 1 人日，但静态化收益打折。

## 7. 迁移前检查清单

按顺序逐项确认，全部通过才进入迁移实施：

1. **数据就绪**（3.0.0 已具备）：`page_data()` 覆盖全部公共路由；所有公开页面只调用一次 `/api/bootstrap`，不再逐页拼接口。
2. **无请求上下文**（3.0.0 已具备）：`python -m app.scripts.check_public_render` 通过且无豁免清单。
3. **路径分页**（3.0.0 已具备）：公共列表页使用路径式分页，旧 `?page=` URL 301 到新路径并有测试；迁移时只需按路径生成静态页。
4. **媒体就绪**：`derivative_set.ready` 覆盖公开内容引用的全部图片；构建脚本在未 ready 时明确失败。
5. **错误页**：404/500 页面在静态托管下的行为已定义（静态 404 页 + 兜底规则）。
6. **构建器可复现**：同一数据库与同一代码构建产物一致（派生图 token 稳定、无时间戳漂移）。
7. **发布可回滚**：新产物原子切换，失败保留上一版；回滚不需要重建。
8. **触发闭环**：内容/外观变更 → `rebuild_site` 任务 → 构建 → 切换；定时发布到点可触发。
9. **缓存切换**：`/_astro` 与媒体 URL 的缓存头符合“不可变 + 长缓存”；旧产物有清理策略。
10. **接入层更新**：nginx 托管静态文件的路由/缓存规则写入运维 vhost，并按 [`EDGE.md`](EDGE.md) 核对清单复验。
11. **规模验证**：500 篇以内全量构建 ≤ 60s；超过时评估增量/分区方案。
12. **文档更新**：迁移完成后重写 README/DEVELOPMENT 的渲染与部署章节，并把本文归入归档。

## 8. 触发点与不迁移的后果

**建议的迁移触发点**：内容规模接近压测上限、公共流量峰值导致 SSR 成为瓶颈、或需要将站点托管到纯静态 CDN 时。三者都应以监控数据（5xx、429、TTFB）为依据，而不是凭感觉。

**不迁移的后果**：保持 SSR 时每页仍有组装成本，接入层缓存只能做到 TTL 级；流量峰值需要靠缓存与限流吸收。但由于 R1–R7 已预留，未来迁移主要是基础设施工作；若不做预留，迁移会重新触碰页面模板与数据访问层（估计多 3~5 人日返工）。
